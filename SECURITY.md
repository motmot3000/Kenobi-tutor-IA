# Security

Kenobi handles API keys that cost money and conversations that may be personal. This page says where each piece of
data goes, what protects it, and how to report a problem.

## Reporting a vulnerability

Please **do not open a public issue**. Use GitHub's private reporting: the repository's **Security** tab ›
**Report a vulnerability**. Describe the problem, how to reproduce it and its impact. You will get an answer within
a week; a fix and a credit (if you want one) follow as soon as possible.

## The web version (static site)

There is no Kenobi server. The page is a set of static files; everything else happens in your browser.

| Data | Where it lives | Where it goes |
|---|---|---|
| Courses, sessions, memory, settings | IndexedDB of the site, in your browser profile | Nowhere. « Exporter mes données » writes a backup file on your computer. |
| AI API key | The vault (below) | Only to the provider you chose, in the `Authorization` (or `x-api-key`) header of its own API, directly from your browser |
| Voice API key (Mistral, ElevenLabs) | The vault | Only to that provider |
| Pairing codes of the bridges | The vault | Only to `127.0.0.1` |
| Your messages, code, files you attach, terminal runs Kenobi sees | Your browser, then the AI provider | The AI provider, to answer |
| Your voice | Your browser | The voice provider if you use an API key; your own computer with the local voice bridge |

### The vault (`browser/vault.js`)

Settings › Modèle d'IA › « Où garder tes clés »:

- **On this device, encrypted** (default): AES-GCM 256 with a key generated by Web Crypto as **non-extractable**: no
  script can read it, it can only be used to decrypt in this browser profile. Protects against reading the storage
  files or a synced copy of the profile; not against a script running in the page itself.
- **Locked by a passphrase**: AES-GCM 256 with a key derived from your passphrase (PBKDF2-SHA-256, 600 000
  iterations, random salt). The derived key lives in memory only, for the current visit. For shared computers.
- **For this visit only**: nothing is written; keys are forgotten when the tab is closed or reloaded.

« Oublier toutes les clés » erases them. Key names (never values) stay readable so a locked vault can say which keys
exist.

### The page

- A Content Security Policy forbids inline scripts and scripts from other origins (`script-src 'self'`). All
  libraries are vendored in `assets/vendor/` with their licenses. No analytics, no tracking, no font or CDN request.
- Model output is rendered with escaping (`core.js`): no HTML from the model reaches the page.
- `connect-src` allows HTTPS APIs (any provider, including a custom OpenAI-compatible endpoint you type), and
  loopback only for HTTP (local models, the bridges).

**Advice**: use a dedicated API key with a spending limit, and revoke it if you think it leaked. On a shared
computer, choose the passphrase or the visit-only mode, and erase the site's data when you leave.

## The bridges

`kenobi-terminal.py` (terminal) and `kenobi-voice.py` (local Whisper and Piper) run on your computer, on request.

- They listen on `127.0.0.1` only and refuse any `Host` header other than loopback (protection against DNS
  rebinding).
- They require a **pairing code** (`<port>-<token>`, 32 random bytes) that only the page you paired knows; it is
  stored in a private file (0600) and can be renewed with `--nouveau-jeton`.
- They only answer pages whose origin is allowed: the address of the Kenobi page you downloaded them from, the local
  ones, and `--kenobi <address>`. CORS answers include `Access-Control-Allow-Private-Network` for that origin only.
- The terminal bridge never types anything by itself: Kenobi reads runs, the learner types. Obvious secrets are
  masked before a run is sent to Kenobi.

## The self-hosted version (`server.py`)

- Listens on `127.0.0.1` by default (`KENOBI_HOST` to open it to your network).
- Keys live in `~/.config/kenobi/settings.json` (0600, ignored if other accounts can read it), never sent back to the
  browser: the page only learns that a key exists.
- Settings can only be changed from the computer that runs the server (loopback client and `Host`), unless
  `KENOBI_REMOTE_SETTINGS=1`.
- The optional voice gateway (`gateway.py`, for an outside call app) is closed until its token file exists and
  only answers loopback requests with that token.
- No HTTP log, no message content in any log.

## Supported versions

Only the latest release (the `main` branch and the published site) receives security fixes.
